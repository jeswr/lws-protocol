The application/lws+json Media Type

The following registration templates follow [[RFC6838]] Section 5.6 and are subject to standards-tree review.

This specification requests registration of the application/lws+json media type specifically for identifying documents conforming to the fixed JSON layout for LWS containers, access requests, access grants, notifications, or webhook subscriptions.

  • Type name: application
  • Subtype name: lws+json
  • Required parameters: None
  • Optional parameters: None
  • Interoperability considerations: Uses JSON-LD vocabulary mappings with the additional fixed layouts defined in . Arbitrary JSON or JSON-LD does not imply this profile.
  • Fragment identifier considerations: The +json suffix rules in [[RFC6839]] apply. This media type defines no additional fragment syntax; JSON Pointer semantics are not implied.
  • Published specification: This specification, Linked Web Storage Protocol 1.0 (Working Draft; registration remains proposed).
  • Applications that use this media type: Linked Web Storage clients and servers implementing the advertised fixed JSON representation.
  • Additional information: Deprecated alias names: none; magic numbers: none; file extensions: none specified; Macintosh file type codes: none specified.
  • Intended usage: COMMON
  • Restrictions on usage: None.
  • Author: W3C Linked Web Storage Working Group.
  • Change controller: W3C.
  • Provisional registration: No.
  • Encoding considerations: Resources that use the application/lws+json media type are required to conform to all of the requirements for the application/json media type and are therefore subject to the same encoding considerations specified in Section 11 of [[RFC8259]].
  • Security considerations: See and . JSON-LD context processing MUST preserve policy constraints and MUST NOT grant authority to untrusted remote contexts.
  • Person and email address to contact for further information: W3C Linked Web Storage Working Group <public-lws-wg@w3.org>

Note that while the Linked Web Storage format uses JSON-LD conventions, there are a number of constraints and additional requirements for LWS implementations that justify the use of a specific media type.

Support for this representation is optional and advertised as defined in . Generic JSON-LD and JSON media types do not imply this layout.

The application/lws+cid Media Type

This specification requests registration of the application/lws+cid media type for identifying storage description documents conforming to the Linked Web Storage protocol as a specialization of the W3C Controlled Identifiers 1.0 document format.

  • Type name: application
  • Subtype name: lws+cid
  • Required parameters: None
  • Optional parameters: None
  • Interoperability considerations: A specialization of [[CID-1.0]] with the LWS storage description model and context sequence; see .
  • Fragment identifier considerations: Follows the CID fragment semantics in [[CID-1.0]]. No additional LWS fragment syntax is defined.
  • Published specification: This specification, Linked Web Storage Protocol 1.0 (Working Draft; registration remains proposed).
  • Applications that use this media type: Linked Web Storage clients and servers implementing the advertised fixed JSON representation.
  • Additional information: Deprecated alias names: none; magic numbers: none; file extensions: none specified; Macintosh file type codes: none specified.
  • Intended usage: COMMON
  • Restrictions on usage: None.
  • Author: W3C Linked Web Storage Working Group.
  • Change controller: W3C.
  • Provisional registration: No.
  • Encoding considerations: Resources that use the application/lws+cid media type are required to conform to all of the requirements for the application/json media type and are therefore subject to the same encoding considerations specified in Section 11 of [[RFC8259]].
  • Security considerations: See , , and [[CID-1.0]]. A storage description does not itself establish trust in an issuer.
  • Person and email address to contact for further information: W3C Linked Web Storage Working Group <public-lws-wg@w3.org>
